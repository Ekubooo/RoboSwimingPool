# 刚体 GPU 直写与流体独立时钟：实现与验证

日期：2026-11-14。环境：Windows、RTX 5070、Newton 1.7.0、Warp 1.18.0。

## 改动

- `RSP/rendering/rigid.py` 管理共享实例缓冲。变换、颜色、透明度值由 CUDA
  直接写入 OpenGL；复用原有网格和着色器，预先准备胶囊柱体和端帽。
- `newton_gl.py` 连接现有 ViewerGL 场景、相机、UI、拾取及录像。普通刚体
  更新不再回读变换和颜色；透明度跨绘制通道的变更使用显式刷新通知。
- 关闭质心显示时跳过其计算和上传。事件轮询改为当前渲染器实例上的非阻塞
  轮询，原有应用限帧保持不变。CUDA 注册在关闭窗口前释放。
- `RSP/runtime` 提供代码配置、独立流体时钟及调度适配器。PBF、MuJoCo 数值
  实现未改动。现有后端只修改获准的两个接线文件，Actuation、Presentation、
  人形设置和资产管线未改动。

参数入口是 `RSP/runtime/fluid_clock.py` 的 `DEFAULT_SETTINGS`。默认倍率 0.2、
基础子步 3、压力迭代 3、返力倍率 1、最大积分步长 1/300 s。完整物理参数
复用 `PBFConfig`，启动前修改，本轮没有参数 UI。

人形控制保持 30 Hz、刚体保持 240 Hz。每个控制帧默认流体推进 1/150 s，
在第 3、6、8 个刚体子步各运行一次 1/450 s 的 PBF。最近的原始返力在各
刚体子步保持并施加一次。暂停流体时跳过积分和返力；重置同时清理流体时钟。

## 三组性能对比

同场景、同策略检查点、同随机种子、195,525 粒子、18 刚体、1280×720、
保留真实 UI、关闭 VSync。每组 3 个独立进程；每次预热 30 帧后测量 180 帧。
以下统计合并每组 540 个不限帧样本；截图和 GPU 排空在测量区间外。

| 场景 | 整帧均值 | 整帧 P50 | 整帧 P95 | 渲染均值 | 刚体更新均值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A：改动前，原流体推进 | 41.28 ms | 40.50 ms | 49.92 ms | 8.10 ms | 3.88 ms |
| B：新渲染，原流体推进 | 37.29 ms | 35.80 ms | 43.62 ms | 4.68 ms | 0.82 ms |
| C：新渲染＋默认独立时钟 | 23.86 ms | 23.40 ms | 28.89 ms | 4.16 ms | 0.72 ms |

| 场景 | 渲染 P50 / P95 | 刚体更新 P50 / P95 | 三次整帧均值 |
| --- | --- | --- | --- |
| A | 8.09 / 9.95 ms | 3.77 / 4.98 ms | 39.07、43.72、41.04 ms |
| B | 4.24 / 7.53 ms | 0.74 / 1.30 ms | 36.06、41.21、34.60 ms |
| C | 3.89 / 6.32 ms | 0.68 / 1.04 ms | 23.24、25.14、23.21 ms |

整帧均值从 A 到 C 降低约 42.2%。B 固定倍率 1、8 子步、1/240 s，单独
衡量渲染改动；其渲染改动包含 GPU 直写、隐藏质心跳过及事件轮询调整。
C 每控制帧推进的流体时间是 A/B 的 1/5，并减少流体调用次数；这部分收益
属于用户选择的播放策略，不能解释为相同物理推进量下的求解器加速。

这些是 CPU 调用耗时，包含驱动和互操作等待，并非纯 GPU 着色耗时。
“刚体更新”是 `log_state` 扣除粒子更新后的耗时，包含保留的非粒子场景工作。
完整批次排空后的均值分别为 41.28、37.30、23.87 ms，与逐帧计时一致。
常规限帧下 C 平均约 34.10 ms，继续服从原来的约 30 FPS 运行节奏。

初次新渲染测试曾被窗口轮询等待抵消收益。改为非阻塞轮询后，B/C 的事件
处理均值约 0.07/0.06 ms。较早的 `stage3_B_1`、`stage3_C_1` 属于诊断结果，
上表使用 `stage3_final_B_*`、`stage3_final_C_*`，未混入这些诊断样本。

原始数据：`output/rsp_render_profile/stage3_summary.json`；各组的完整逐帧数据
位于 `stage3_A_1..3`、`stage3_final_B_1..3`、`stage3_final_C_1..3`。

## 功能检查

- 14 项渲染检查通过：含胶囊端帽、动态颜色、常规帧无回读/主机上传、深度
  遮挡、透明度刷新、拾取、COM 开关、关闭窗口前释放注册及现有 UI。
- 5 项时钟/返力/Graph 生命周期单元检查、9 项后端回归检查通过；未改动的
  资产管线另以独立进程运行，7 项通过。
- 默认、2 子步、暂停、加速档均通过真实场景检查，每档保存 630 项有限值
  状态/反馈快照，检查外力输入、稳定的借用缓冲、重置及恢复推进。暂停档
  另外验证粒子位置和速度保持不变。加速档实际每控制帧调用 10 次流体更新。
- SMP 检查点加载、GSI 重置、8 帧策略运行和 GL 录像通过。
- 默认 Graph 与普通执行的 630 项快照中 597 项逐位一致。其余差异出现在
  接触后的浮点状态与力：粒子位置最大差约 0.72 微米，粒子速度约 0.00015
  m/s，刚体返力最大差约 0.021（对应分量约 402）。时钟与步数一致。严格
  `rtol=1e-5, atol=1e-6` 下 10 项数组不通过，因此不宣称逐位确定性；完整
  差异保存在 `output/newton_pbf_refactor_checks/stage3_graph_eager_comparison.json`。
  同配置 Graph 独立重复也有 27 项数组出现小幅差异，说明本身存在浮点
  非确定性；未为追求逐位一致更改既有求解器。

## 视觉稳定性与限制

默认配置连续运行 1,800 个控制帧，即主时钟 60 秒、流体时钟 12 秒。
检查点中的粒子、人形、返力和观测均为有限值；关键截图显示主体水面、人形、
刚体和 UI 正常，没有发现大规模数值爆炸或渲染错位。

但最终有 **4 / 195,525 个粒子（约 0.002%）越出池体**并继续下落，最远
低于池底约 67 m。因此本次不能宣称“零粒子泄漏”。当前边界投影依赖有效
SDF 梯度，且动态边界投影发生在静态边界投影之后；这为少量粒子逸出提供了
需要进一步排查的路径。追加的原推进节奏（倍率 1、8 子步、每步 1/240 s）
60 秒主时钟对照最终为 **0 个越界粒子**，因此新时序下的少量泄漏仍需处理，
不能将其直接认定为原场景已有现象。对照数据在 `stage3_legacy_stability`。
本轮没有更改该核心求解逻辑，
也没有删除或隐藏越界粒子来掩盖现象。

关键截图和最终状态在 `output/rsp_render_profile/stage3_final_C_1/`。
可选的 COM、碰撞诊断、拾取以及 UI 检查器仍使用 Newton 的实现，可能读取
GPU 数据；本次消除的是常规刚体实例更新中的状态和颜色回读。
