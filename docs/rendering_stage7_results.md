# 拖拽恢复、低水块布局与短 GPU 诊断

日期：2026-11-15。

## 改动

- `RSP/rendering/picking.py`：为 Newton 的鼠标选取建立只含可见形状的模型视图，缓存六组形状数组，保留原刚体编号及施力缓冲。碰撞模型不变。原生 raycast 不检查可见标记，池子不可见的封闭碰撞墙会抢先截获射线。
- `RSP/rendering/newton_gl.py`：创建或切换模型时接入该视图；显式外观失效时重建。正常帧不增加筛选或回读。
- `RSP/rendering/playback_ui.py`：补充右键拖拽提示，继续使用 Newton 的鼠标处理、弹簧/阻尼施力和辅助线。交互期间仍可能回读；没有宣称拖拽也完全无回读。
- `mimickit/envs/pbf_play_env.py` 与环境 YAML：取消调用“抬到水块上方”的场景放置逻辑，仅将人形根节点的 XY 设为 `(0.65, 1.0)`。MimicKit/GSI 的初始化姿态、根高度、速度保持原值。本次种子下根高度为 0.903527 m。
- `RSP/runtime/fluid_clock.py`：只改初始水块边界。没有改后端文件、求解器、PD、策略模块或资产生成算法；没有接入粒子筛选。

| 世界 Y 边界 | 0.75～1.90 m | 0.04～1.96 m |

实际新粒子中心范围为 X=1.34～2.94、Y=0.06～1.94、Z=0.04～0.80 m。
保持半径 0.01 m、流体 2 子步/3 次压力迭代、time_scale=1、feedback_scale=1。
每帧推进 1/150 s，刚体 4×1/600 s，流体 2×1/300 s，策略每 5 帧推理，PD 参数不变。

## 必要检查

- 同一相机射线：原生选取命中 `pool_wall_2`，无可拖拽刚体（body=-1）；修复后命中人形 body=0。
- 经过 Viewer 鼠标按下/拖动/松开接口，目标移动 0.4204 m。普通施力调用得到范数 319.56，生产 CUDA Graph 后为 319.42；松开后独立施力缓冲为零。
- 暂停不推进；单步仅推进 1/150 s；暂停时重置清空两套时钟。
- 1 项默认配置定向单元测试通过，确认新网格数量、坐标转换以及原时间配置。
- 连续运行 600 帧，即 **4 秒模拟时间**；在 1/2/3/4 秒检查粒子、速度、刚体、关节、观测及返力，均有限，粒子越界数为零。
- 遵照用户决定，**不筛除兔子内部粒子**：初始 6,103 个粒子位于静态实体内部，其中 5,048 个穿透超过半径。1 秒及后续检查点均为零。启动阶段存在局部飞溅：1 秒采样的最高粒子为 2.713 m，4 秒时为 0.726 m。这是重叠初始化下的观察结果，不保证后续任意配置均无飞溅。
- 未运行全套回归、长时间稳定性或录像测试。截图与状态检查均在计时区间外。

## 测量方法

RTX 5070，1280×720，可见窗口，VSync 关闭，MSAA=4，阴影保持开启；原 SMP 策略，随机种子 1234。

正常播放预热 30 帧、测量 60 帧一次。场景与 UI 用 OpenGL `GL_TIME_ELAPSED` 查询，批末才取结果；CPU 墙钟记录帧、map/unmap 和 present 等调用。包含少量计时插桩开销。

另做短诊断：在原 CUDA Graph 的 4 次刚体调用和 2 次 PBF 调用两侧插入 CUDA timing events，预热 10 帧、测量 30 帧。每帧物理提交后同步以读取事件，改变了流水重叠；因此其整帧不能作为正常吞吐成绩。计时 Graph 只在工具进程中创建，不改生产 Graph 实现。第一轮诊断捕获尝试使用导入的 Torch 默认流而失败，改用 Warp 自有流后仅补跑 GPU 诊断，复用已完成的正常帧和正确性结果。

不同采样区间的状态、渲染视角和 GPU 调度可能不同；这不是逐帧严格配对的性能归因。与上一阶段隐藏窗口的历史结果也不作严格速度提升比较。

### 正常播放 CPU 墙钟

单位 ms，均值 / P50 / P95；渲染子项属于父区间，不能重复相加。

| 项目 | 均值 | P50 | P95 |

| 整帧 | 8.228 | 8.606 | 10.332 |
| 策略推理（所有帧平均） | 0.065 | 0.000 | 0.321 |
| 动作处理 | 0.067 | 0.065 | 0.094 |
| 仿真提交 | 0.468 | 0.457 | 0.598 |
| 后处理/观测 | 0.082 | 0.073 | 0.135 |
| 渲染调用（含等待） | 7.492 | 7.901 | 9.729 |
| 刚体实例更新 | 0.203 | 0.186 | 0.320 |
| 粒子更新 | 0.128 | 0.121 | 0.199 |
| 场景绘制提交 | 0.493 | 0.457 | 0.732 |
| UI 构建 | 0.062 | 0.057 | 0.092 |
| UI 绘制提交 | 0.231 | 0.217 | 0.326 |
| 窗口事件 | 0.141 | 0.032 | 0.387 |
| 交换显示 present | 5.990 | 6.361 | 8.320 |
| CUDA–GL map | 0.067 | 0.061 | 0.090 |
| CUDA–GL unmap | 0.030 | 0.027 | 0.042 |
| CUDA–GL map+unmap | 0.096 | 0.090 | 0.132 |

正常循环均值对应约 **121.5 FPS**；计入批末排空 GPU/GL 后为 **8.611 ms/帧，约 116.1 FPS**。短批次的尾部等待不能忽略，8.228 ms 只表示循环内帧间隔。map/unmap 是 CPU 调用区间，包含 API/驱动开销及可能的等待，不能称为精确的“纯等待”。它们同时包含在实例/粒子更新及渲染父区间中。

### GPU 分段与等待位置

| 项目 | 口径 | 均值 ms | P50 | P95 |
|---|---|---:|---:|---:|
| 刚体推进，4 次合计 | 同步诊断 CUDA events | 1.850 | 1.830 | 2.309 |
| PBF 推进，2 次合计 | 同步诊断 CUDA events | 5.300 | 5.346 | 5.689 |
| 场景实际绘制 | 正常播放 GL elapsed | 0.421 | 0.421 | 0.429 |
| UI 实际绘制 | 正常播放 GL elapsed | 0.007 | 0.007 | 0.007 |
| 场景+UI 实际绘制 | 正常播放 GL elapsed | 0.428 | 0.428 | 0.436 |
| 物理提交后等待 | 同步诊断 CPU 墙钟 | 6.689 | 6.710 | 7.328 |
| 交换显示 present | 同步诊断 CPU 墙钟 | 0.053 | 0.040 | 0.103 |

诊断的 CPU 渲染调用为 3.368 ms，GL 场景+UI elapsed 为 1.172 ms，map/unmap 合计 0.548 ms；同步会改变 CPU/GPU 重叠和调度，不能把它们与正常样本作机械相减。诊断整帧为 11.306 ms，仅用于归因。

**当前主要耗时来自 GPU 仿真，PBF 高于刚体。** 正常播放约 5.99 ms 的交换显示调用含有前序 GPU 工作的等待；提前等待后 present 只剩约 0.053 ms，说明不能把 7.49 ms 渲染调用当成纯绘制。GPU 仿真、GL 绘制、CPU 互操作/显示阻塞具有重叠，以上各表不能相加组成整帧。
