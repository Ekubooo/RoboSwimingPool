# SSFR Water / Velocity：效果与耗时

日期：2026-11-15。实现限定于渲染层，附带专用测试、性能工具和文档；后端、求解器、策略、PD、流体配置及资产管线均未改。

## 使用与效果

- 启动仍默认 Original。在 Fluid rendering 选择 SSFR 后，SSFR material 提供 Water / Velocity，首次为 Water。暂停可切换；Reset、切换到其他渲染模式再回来均保留选择。
- Water 使用原 billboard 蓝色 `(29,119,231)/255` 作为水材质基础色，保留原 RGB 厚度吸收、折射、反射和高光。
- Velocity 复用原 GPU 色带：0 m/s 蓝色、2 m/s 浅蓝 `(160,221,255)/255`、6.5 m/s 及以上白色，分段线性插值。覆盖强度为 `smoothstep(2,6.5,speed)`，均匀高速表面最终为不透明白色，不再叠加反射、折射及高光。
- 为避免浅色区域被选择性 RGB 吸收染成暖色，Velocity 使用现有吸收系数的均值进行中性厚度衰减。Water 保持原 RGB 吸收。低速 Velocity 仍有水材质，但不要求与 Water 逐像素相同。
- 仅最前表面附近两个显示半径内的粒子贡献颜色和覆盖度，按深度距离和径向权重归一化。混合速度区域是局部加权效果，并非一颗高速粒子就把整片水染白。
- Velocity 在厚度绘制时增加颜色/权重和覆盖度附件，复用已有 GPU 实例数据，不增加粒子绘制通道。Water 不执行属性累积；专用资源首次使用时分配并缓存。
- 深度、厚度、平滑、法线和显示半径算法保持现状。原有粒子感、孔隙和闪亮边缘仍存在，本轮没有做连续性改善。

## 必要验证

- 真实 CUDA/GL 定向检查通过：0、2、4.25、6.5 m/s 的颜色与覆盖度；高速中心像素为不透明白色；低速保持蓝色水材质。
- 深层高速粒子不会染白独立的前方低速表面；不透明几何同时遮挡流体及其材质属性。
- 检查失败回退、缓存复用、暂停切换、退出再进入 SSFR、模型更换、缩放和关闭；Original 切回后的固定场景逐像素一致。
- 完整演示的暂停切换过程中，人形/流体时钟不变、仿真 Graph 对象不变；通过实际 UI Reset 请求入口重置后保持 Velocity 并暂停。
- 普通播放帧禁止 Warp `.numpy()` 后仍正常运行；新增路径静态审计无状态回读或显式 GPU 等待。测试中的纹理附件检查、截图和最终 GPU 查询读取均在计时区间外。
- 未测试录像，未生成录像缓存；未执行全套回归或长稳定性测试。发现材质暖色偏移并修正后，只重新检查并采样 Velocity；未重复 Water 性能采样。下表仅使用最终实现的结果。

## 性能

RTX 5070，1280×720，299,475 粒子，相同策略、种子 1234、初始配置和相机。最终 Water、Velocity 各取一个独立进程，预热 30 帧、采样 180 帧一次。

单位 ms，表内为 **均值 / P50 / P95**。CPU 分项互斥，均值可相加；分位数不能相加。策略每五帧推理，因此 P50 为零。

| CPU 墙钟部分 | Water | Velocity |
|---|---:|---:|
| 策略推理 | 0.073 / 0.000 / 0.373 | 0.076 / 0.000 / 0.380 |
| 动作处理 | 0.095 / 0.098 / 0.138 | 0.098 / 0.101 / 0.137 |
| 仿真提交 | 0.591 / 0.555 / 0.757 | 0.615 / 0.569 / 0.860 |
| 观测 | 0.097 / 0.087 / 0.172 | 0.101 / 0.092 / 0.166 |
| 渲染调用（含等待） | 8.554 / 8.545 / 11.012 | 8.654 / 8.684 / 10.994 |
| 其他 | 0.081 / 0.078 / 0.104 | 0.085 / 0.080 / 0.123 |
| 整帧 | 9.489 / 9.467 / 11.813 | 9.630 / 9.709 / 11.895 |

GPU 使用 GL_TIMESTAMP，采样结束后统一读取结果。下面是与 CPU 墙钟重叠的归因数据，不能加到整帧上；完整场景范围包含其子项。

| GPU 绘制范围 | Water | Velocity |
|---|---:|---:|
| Newton 场景 | 0.187 / 0.186 / 0.195 | 0.188 / 0.187 / 0.201 |
| SSFR 流体通道 | 0.519 / 0.520 / 0.535 | 0.577 / 0.575 / 0.612 |
| 完整场景及流体合成 | 0.754 / 0.728 / 0.750 | 0.788 / 0.784 / 0.827 |

Velocity 相对 Water：整帧均值增加 **0.140 ms**，SSFR 流体 GPU 均值增加 **0.057 ms**，完整场景 GPU 均值增加 **0.034 ms**。这是当前视角的一次测量，包含系统波动，不代表所有视角的性能上界。

上一轮历史参考：Original 整帧 8.736 ms，旧 SSFR 整帧 9.025 ms、流体 GPU 0.506 ms。本轮不是同期严格对照，不能把与历史的整帧差额都归因于材质变化。CPU 渲染调用仍包含等待，约 8 ms 不等于实际绘制执行时间。

## 热切换与画面

现有 Presentation 先结束上一帧绘制，再记录下一帧数据。检查工具在暂停状态处理两个循环，确认新配置实际显示后截图与计时；不改后端顺序，也不推进物理时间。以下完成时间含两个暂停循环与 GPU 完成等待，不是单个材质 shader 的执行时间。资源准备 CPU 时间已包含其中。

| 最终 Velocity 进程中的操作 | 资源准备 ms | 完成显示 ms |
|---|---:|---:|
| 保持已启用 Velocity | 0.014 | 5.186 |
| 首次显示 Water | 0.011 | 22.905 |
| 再次切回 Velocity | 0.011 | 6.336 |

## 复现

```text
python tools/profile_rsp_fluid_modes.py SSFR --ssfr-preset Water
python tools/profile_rsp_fluid_modes.py SSFR --ssfr-preset Velocity --check-materials
```

第二条在计时后做短暂停切换/Reset 检查并截图。若只需要交互检查，额外加 `--check-switches`，不重复性能采样。结果和逐帧样本位于 `output/rsp_render_profile/ssfr_presets/`。
